# P1.2 前置：机器人侧执行契约（Mock 链路）

计划 P1.2 需要真机与现场授权，本机不具备。本工作包先把**真机接入前必须定死的规则**
实现为可运行的 Mock 契约，真机到位时只替换传输层，其余不动。

## 一、三条硬规则

| 规则 | 阈值（当前 Mock 值，真机需按本体标定） | 行为 |
|---|---|---|
| 看门狗 | `watchdog_timeout_s = 1.0` | 超时无心跳 → 拒绝一切动作（含从未心跳） |
| 动作维度 | `dof = 6` | 维度不符 → 409 |
| 关节限位 | `joint_limit = 3.2 rad` | 越限 → 409 |
| 单步变化率 | `max_step_delta = 0.35 rad` | 超限 → 409 |
| 急停 | — | 触发后**心跳无效**，必须人工 reset + 重新心跳 |

**设计取舍**：违规一律硬拒绝（409），不做"尽力执行"或自动截断。
理由是真机上截断后的动作不是策略想输出的，静默执行等于制造未记录的行为。

## 二、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/edge/heartbeat` | 喂看门狗；**不解除急停** |
| POST | `/api/edge/actions` | 下发 6 维动作，非法则 409 |
| GET | `/api/edge/status` | 在线/急停/看门狗/计数/阈值 |
| POST | `/api/edge/estop` | 急停（带 reason） |
| POST | `/api/edge/reset` | 人工复位（复位后仍需重新心跳） |

## 三、实测（真实 HTTP）

```
 1 未心跳动作  409   ← 看门狗拦住
 2 心跳        200
 3 合法动作    200
 4 越限动作    409   ← |q|=9 > 3.2
 5 急停        200
 6 急停后动作  409   ← 心跳解不开急停
 7 reset       200
 8 心跳        200
 9 恢复后动作  200
10 status      200
```

## 五、接入真机时要改的（且只改这些）

1. `MockBridge` → `Ros2Bridge` 或 `SerialBridge`（同样的 5 个方法签名）
2. 阈值按实际本体标定：`DOF`、`JOINT_LIMIT`、`MAX_STEP_DELTA`、`WATCHDOG_TIMEOUT_S`
3. 采集侧需补：三路相机时间戳、关节状态、动作回执、心跳来源（工控机 30 Hz）
4. 急停要接**物理回路**，不能只靠软件标志位——软件急停是第二道，不是第一道
